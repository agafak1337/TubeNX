# Открытые вопросы и противоречия ТЗ

Ниже — только то, что нельзя решить внутри макетов: требования ТЗ конфликтуют
друг с другом или допускают две трактовки. В каждом пункте указано, что сделано
в макетах и какое решение нужно принять.

## 1. labelSmall 11 px против минимума 12 px

- §3.3 задаёт `labelSmall` = 11/16.
- §2 и критерии приёмки §9 запрещают кегль меньше 12 px.
- **В макетах:** строка шкалы `labelSmall 11/16` оставлена как спецификация
  (это значение токена), но живые образцы текста на всех страницах — не мельче
  12 px. На `01-tokens` образец подписи был 11 px и увеличен до 12 px.
- **Нужно решение:** либо поднять `labelSmall` до 12/16 в `tokens.json` и
  `tokens.css`, либо разрешить 11 px как исключение для мелких подписей.

## 2. Прозрачности §4.4 против контраста §3.2 / §8

§4.4 фиксирует числовые параметры поверх видео:

| Элемент | Значение §4.4 | Расчётный контраст |
|---|---|---|
| Подпись канала, белый 78 % | поверх нижнего скрима | 11,8:1 на ночном кадре, **3,0:1** на светлом |
| Круг play/pause, чёрный 35 % | белая иконка | 18,1:1 ночной, **3,12:1** светлый, **2,6:1** белое видео |
| Свёрнутая полоса прогресса, белый 18 % | на кадре | **1,15:1** на светлом кадре; прогресс к полосе 1,10:1 |

- §3.2/§8 требуют ≥ 4,5:1 для текста и ≥ 3:1 для графики.
- **В макетах:** значения §4.4 не менялись (это требование ТЗ). Свёрнутая полоса
  показана на тёмном кадре, где она видна (1,69:1 к кадру, прогресс 6,57:1).
- **Нужно решение:** либо ослабить §8 для слоёв поверх видео, либо поднять
  непрозрачности (например, подпись 90 %, круг 45 %, полоса 30 %).

## 3. Поля 24 / карточка 296 против safe area 64 / 36

- §4.2: поля 24, карточка 296.
- §3.4: safe area ТВ 64 по бокам и 36 сверху/снизу, интерактивные элементы
  внутри.
- На 1280: 4·296 + 3·16 = 1232 > 1152 = 1280 − 2·64. Оба требования
  одновременно невыполнимы.
- **В макетах:** для TV выбран вариант A — поля 64, карточка 276, зазор 16
  (4·276 + 3·16 = 1152), высота карточки сохранена 245. Handheld остаётся
  на 24/296 (там safe area нет). Вариант B (24/296) показан на
  `tv-home-variants` как отклонённый.
- **Нужно решение:** подтвердить вариант A для ТВ или ослабить safe area.

## 4. `.slider.is-focus` без кольца в общих CSS

`components.css` содержит `.slider.is-focus { outline: none }`: у слайдера
фокуса остаётся только утолщение дорожки и белое кольцо ползунка, хотя §3.4
требует кольцо 3 px primary снаружи.

- **В макетах:** кольцо добавлено локально в `04-player.html` и `05-tv.html`
  (правило страницы), общий CSS не менялся.
- **Нужно решение:** перенести кольцо в `components.css` (это изменение
  дизайн-системы, требует согласования).

## 5. Фокус поверх видео не описан в дизайн-системе

- `.is-focus` в `components.css` даёт только кольцо `primary`. На светлом кадре
  primary к белому ≈ 1,4:1 — фокус не виден.
- **В макетах:** на страницах Player и TV к кольцу добавлена тёмная обводка
  `box-shadow: 0 0 0 7px rgba(0,0,0,.7)` и подложка `primaryContainer` для
  кнопок и чипов. Это локальные правила страниц.
- **Нужно решение:** добавить в систему вариант `.on-video.is-focus` с тёмной
  обводкой, чтобы страницы не дублировали его.

## 6. Тач-таргеты меньше 48 px

- §3.4: зона нажатия ≥ 48×48.
- Фактически: `.chip.on-video` — 36 px (обёртка `.tap` 48 есть только в
  `04-player.html`), `.btn.text` — 40 px (диалог закрытия, карточка ошибки,
  текстовые кнопки настроек).
- **В макетах:** визуальные размеры не менялись (они утверждены), зона нажатия
  шире видимой только у чипов плеера.
- **Нужно решение:** либо считать 40/36 допустимыми для геймпада, либо
  увеличивать зоны нажатия в разработке (без изменения картинки).

## 7. Монохромная иконка: белый знак или белая марка

- §6 требует «монохромную версию 256 (белый знак на прозрачном)».
- `icon-mono-256.png` — белый squircle с вырезанным прозрачным треугольником
  (белая марка, а не отдельный треугольник). На тёмном фоне читается, на
  светлом белое на белом исчезает.
- **В макетах:** на светлой плитке `06-icon` используется инлайн-копия,
  перекрашенная в `onSurface`.
- **Нужно решение:** подтвердить, что «белый знак» = белая марка со сквозным
  треугольником; иначе нужен отдельный файл «только треугольник».

## 8. `.center-btn` привязан к 1280×720

`app.css` задаёт `.center-btn { left: 598px; top: 318px }`. На других размерах
кадра кнопка не центрируется.

- **В макетах:** все фреймы плеера ровно 1280×720, поэтому не проявляется.
- **Нужно решение:** заменить на `left: 50%; top: 50%; transform:
  translate(-50%, -50%)` при переносе в разработку.

## 9. Две колонки настроек не сходятся арифметически

- §4.5: «две колонки по 560, зазор 24, поля 24».
- 24 + 560 + 24 + 560 = 1168, справа остаётся 112 px — макет становится
  асимметричным.
- **В макетах:** выбран вариант B, как в утверждённом handheld: колонки
  x = 56 и x = 640 по 560 (левое поле 56, правое 80). Оба варианта показаны
  на `settings-layout-variants`.
- **Нужно решение:** закрепить в ТЗ поля 56/80 (вариант B) либо пересчитать
  ширину колонки под симметричные 24.

## 10. Иконка пустого поиска: `surfaceVariant` не видна

- §4.3 предписывает иконке пустого состояния цвет `surfaceVariant`
  (в тёмной теме ≈ 2:1 к фону).
- **В макетах:** используется `outline` (≈ 5:1).
- **Нужно решение:** поправить §4.3 на `outline` (или `onSurfaceVariant`
  с пониженной непрозрачностью).

## 11. Кольцо фокуса у строк списка рисуется внутрь

- §3.4: кольцо 3 px снаружи + зазор 2 px.
- `components.css`: `.li.is-focus` использует `outline-offset: -3px`, иначе
  кольцо срезается `overflow: hidden` у `.menu`.
- **В макетах:** оставлено как в библиотеке; на карточках и кнопках кольцо
  снаружи, как в ТЗ.
- **Нужно решение:** разрешить для строк меню/списков кольцо внутрь.

## 12. `audit` не видит фон псевдоэлементов и обложек

`wd.mjs audit` считает контраст по фону родителя: у сфокусированной `.vcard`
фон — `::before` (`primaryContainer`), у текста поверх обложек — `.th`.
Поэтому такие пары проверены вручную по пикселям (карточка в фокусе —
7,16:1, подпись канала — 5,71:1).

- **Нужно решение:** это ограничение инструмента, не макета; при приёмке
  учитывать ручные расчёты из отчёта.
