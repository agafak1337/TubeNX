# Hardware smoke: чек-лист на консоли

Цель — за один прогон понять, работает ли сборка на реальной Nintendo Switch,
и собрать логи, по которым можно чинить проблемы без автора.

Время: 15–20 минут. Нужны: консоль, SD-карта, Wi-Fi, hbmenu.

## Подготовка

1. Соберите диагностическую сборку:

   ```bash
   export DEVKITPRO=/path/to/devkitpro
   make diag            # TubeNX-diag.nro
   ```

2. Скопируйте `TubeNX-diag.nro` в `sd:/switch/`.
3. Убедитесь, что на SD есть место (лог + кэш).
4. Вставьте SD, запустите hbmenu.
5. Приготовьте `tools/pull-log.sh` на компьютере.

## Чек-лист (12 шагов + crash-тест LOG-05)

Отмечайте `OK` / `FAIL` и коротко что видели. Для `FAIL` сразу указывайте
время — по нему ищется строка в логе.

| № | Шаг | Что ожидается | OK/FAIL |
|---|---|---|---|
| 1 | Запуск из hbmenu | иконка TubeNX видна, приложение стартует, сплэш с прогрессом | |
| 2 | Главный экран | лента или понятная ошибка; чипы «Главная/В тренде/Поиск…»; обложки или placeholder | |
| 3 | Навигация | стик/D-pad двигают фокус, A открывает, B назад, Y пауза в плеере | |
| 4 | Поиск | X открывает клавиатуру, запрос уходит, подсказки/результаты появляются | |
| 5 | Видео: старт | тап/A по видео → плеер, картинка и звук, без чёрного экрана | |
| 6 | Видео: 60 секунд | непрерывное воспроизведение 60 с, `avsync` в пределах ±50 мс, дропы не растут лавиной | |
| 7 | Seek ×10 | L/R или перемотка: позиция меняется, звук возвращается, картинка не залипает | |
| 8 | Качество 720→480 | смена в меню плеера: позиция ±2 с, без падения и чёрного экрана | |
| 9 | Сон 30 с (HOME) | уход в фон → пауза; возврат → видео продолжается или стоит на паузе, звук есть | |
| 10 | Выход и hbmenu | B → «Закрыть видео?» → выход; в hbmenu нет «медиа играет» | |
| 11 | Настройки и конфиг | тема, качество, звук, обход DPI; после перезапуска настройки на месте | |
| 12 | Dock/handheld и тач | подключение к TV: картинка не растянута, тач попадает в кнопки; обратно в handheld | |
| 13 | Аварийный лог (LOG-05) | создать пустой файл `sd:/switch/TubeNX/crash-test` и запустить NRO: приложение намеренно падает, в `sd:/switch/TubeNX/logs/crash.log` есть сигнал и хвост ring-буфера; флаг переименован в `crash-test.used` | |

### Что писать в `FAIL`

- шаг и время (например, `6, 14:32`);
- что на экране (чёрный экран / спиннер / ошибка / звук есть, видео нет);
- что было до шага (перемотка, смена качества, сон);
- повторяется ли после перезапуска.

## Какие строки искать в логе

| Что проверяем | Строка |
|---|---|
| Версия и режим | `start v=… build=… mode=…` |
| Wi-Fi | `wifi: тип=… сигнал=…/3 статус=…` |
| Конфиг | `config: dark=… seed=… reco=… history=…` |
| DPI | `dpi socks: listen 1080`, `dpi relay: запущен` |
| Bootstrap | `feed: ok=1 …` или `feed: ok=0 … err='…'` |
| Потоки | `streams: pickStreams …` / `player: open … itag=…` |
| Плеер | `player: state … Opening → FileLoaded → Playing` |
| Метрики | `player metrics: pos=… avsync=… vbitrate=… abitrate=…` |
| Кадры | `perf: … fps=… drawn=… skip=… rows=…/720` |
| Сон | `PL-03: приложение в фоне/сне`, `PL-03: пробуждение` |
| Ошибки | `diag http: … status=… err='…'` |
| HTTP/TLS (NET-17) | `http: … h2=…`, сводка «1–2 новых TLS-рукопожатия» на 10 запросов |
| DNS (NET-16) | `dns: … ip=… resolve=…ms`; при сломанном первом A-рекорде — переход на второй IP |
| Скорость (NET-18) | `speed: status=200 bytes=1500000 … КБ/с` |
| Аварийный лог (LOG-05) | `crash.log`: `signal=…`, `ring:` и последние строки boot-лога |

## Сбор результата

1. Выйдите в hbmenu.
2. На компьютере:

   ```bash
   bash tools/pull-log.sh
   ```

3. В приложении: «Настройки → Диагностика → Скопировать лог» →
   `sd:/config/TubeNX/diagnostics.txt`.
4. Сложите в одну папку:

   ```
   logs/hardware-boot.log
   logs/diagnostics.txt
   screenshots/…        (если есть)
   ```

5. Заполните шаблон ниже и приложите файлы. Не обрезайте лог до одной
   удачной строки.

## Шаблон отчёта

```markdown

- Режим: handheld / dock
- Сборка: TubeNX-diag.nro, build=<sha>
- Провайдер/регион: <…>
- Обход DPI: вкл/выкл, режим <Split/Multi/Disorder/TLS>
- Внешний прокси: нет / <scheme://host:port>

## Результаты

| № | Шаг | Результат | Комментарий |
|---|---|---|---|
| 1 | Запуск | OK/FAIL | |
| … | | | |

## Проблемы

1. Шаг 6, 14:32 — видео встало через 20 с, в логе `player: state
   Playing → Paused`, `avsync=-0.8`. Повторяется.
2. …

## Логи

- logs/hardware-boot.log
- logs/diagnostics.txt

## Что уже пробовал

- выключал/включал обход DPI;
- менял режим Split → Multi;
- перезапускал приложение.
```

## Если что-то пошло не так

- **Приложение не появилось в hbmenu** — проверьте, что скопирован именно
  `.nro`, а не `.elf`; пересоберите `make`.
- **Чёрный экран на старте** — подождите 10 с, затем HOME → выход; заберите
  `TubeNX-boot.log`, там будет причина.
- **Нет лога на SD** — проверьте, что SD смонтирована и не read-only; баннер
  в настройках скажет об этом.
- **Видео не открывается, API работает** — см. `docs/network.md` §2.3–2.4,
  вероятна блокировка CDN; попробуйте внешний прокси.

См. также: `docs/network.md` (ошибки), `docs/architecture.md` (потоки),
`handoff/deepseek/OPEN_QUESTIONS.md` (что именно ещё не подтверждено).
