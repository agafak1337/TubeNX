# Как делать дизайн TubeNX

Практическое руководство для дизайнера: как устроен «макет», какими
инструментами он собирается, что можно менять и как передать результат в код.

Дизайн-система уже собрана. Здесь — правила для новых экранов, состояний и
правок, а не «нарисуй проект с нуля».

---

## 1. Где что лежит и что главнее

| Что | Где | Статус |
|---|---|---|
| ТЗ на дизайн | [`docs/design-tz.md`](design-tz.md) | **источник правды**, главнее макета |
| Макет («Figma») | `design/` | HTML-доски + ассеты + экспорт |
| Токены | `design/tokens.json`, `design/assets/tokens.css` | генерируются из кода |
| Связь токенов и кода | [`docs/design-tokens.md`](design-tokens.md) | таблица «дизайн → код» |
| Матрица компонентов | [`docs/m3-matrix.md`](m3-matrix.md) | состояния и доступность |
| Код интерфейса | `source/ui/`, `source/md3/`, `source/core/` | зона разработчика |

Правила границ:

- **дизайнер не правит `source/`** — только `design/` и документы;
- **разработчик не правит `design/`** — только реализует макет;
- если ТЗ и макет расходятся, прав ТЗ; расхождение описывается в PR;
- общие файлы `design/assets/*.css` одновременно используют все страницы:
  не правь их под одну задачу, пиши локальный `<style>` на своей странице.

## 2. Что уже есть в `design/`

```
design/
  screens/            8 страниц-досок, каждая = страница «Figma»
    00-cover.html
    01-tokens.html
    02-components.html
    03-screens-home.html
    03-screens-search.html
    03-screens-settings.html
    04-player.html
    05-tv.html
    06-icon.html
    07-motion.html
    _reference.html   образец разметки, от него отталкивайся
  assets/
    tokens.css        роли M3 как CSS-переменные, темы .dark/.light
    base.css          шрифты, типографика, доска, фрейм, safe area
    components.css    Button, Chip, Switch, Slider, Card, Dialog, …
    app.css           app bar, сетка, карточки видео, плеер, пустые состояния
    frame.js          ?frame=<id> и ?scale=1.5
  tokens.json         экспорт токенов (37 ролей, 12 ролей текста, формы)
  png/                отрендеренные PNG по страницам
  export/             иконки и SVG-иллюстрации для кода
  tools/              рендер, аудит, контраст, сборка токенов, иконка
  handoff/            отчёты прошлых дизайн-агентов
```

Каждая доска — это набор фреймов 1280×720. Фрейм — `<div class="frame dark"
id="уникальный-id">`; вокруг него `.shot` с `.name` («Home / Загрузка /
Тёмная») и `.spec` (сетка, отступы, размеры, роли цветов).

## 3. Что установить

Нужны:

- **Firefox** — рендер HTML в PNG;
- **geckodriver** — управление Firefox для `wd.mjs`;
- **Node.js 22+** — инструменты в `design/tools/`;
- **g++** — только если пересобираешь токены из `source/md3/theme.cpp`.

Проверка:

```bash
firefox --version
geckodriver --version
node --version
```

Если `geckodriver` не в PATH, положи его в `~/.local/bin` или добавь путь в
`PATH`. `wd.mjs` запускает его сам.

Проверка, что доска читается:

```bash
cd TubeNX
node design/tools/wd.mjs frames screens/03-screens-home.html
```

Команда печатает id и размеры всех фреймов страницы.

## 4. Ежедневные команды

Команды выполняются из корня репозитория. Аргумент страницы (`screens/...`) и
папка экспорта (`png/...`) — относительно `design/`.

### Посмотреть фреймы

```bash
node design/tools/wd.mjs frames screens/03-screens-home.html
```

### Отрендерить все фреймы страницы

```bash
node design/tools/wd.mjs shoot screens/03-screens-home.html png/03-screens-home
```

PNG появятся как `<frame-id>.png`, размер — размер фрейма.

### Отрендерить один фрейм

```bash
node design/tools/wd.mjs shoot screens/03-screens-home.html /tmp/out home-focus
```

Или через headless Firefox без geckodriver:

```bash
bash design/tools/render.sh screens/03-screens-home.html /tmp/home-focus.png home-focus
```

### Машинный аудит

```bash
node design/tools/wd.mjs audit screens/03-screens-home.html
```

Проверяет: уникальность id, размеры, кегль < 12 px, иконки вне сабсета,
выход за фрейм, обрезку текста, `blur`/`backdrop-filter`/курсив, тени,
контраст. Это не замена глазам, но ловит механические ошибки.

Известный шум, который не является дефектом:

- `opacity: .38` у disabled-элементов — требование M3;
- тени у `menu`/`dialog`/`snackbar` — разрешены;
- «курсив» на пустых `<i>` (полоски, фигуры) — текста внутри нет;
- контент, обрезанный краем экрана в скролле, — задуманная обрезка.

### Контраст

```bash
node design/tools/contrast.mjs
node design/tools/contrast.mjs --json
```

Таблица пар текст/фон. Нужно ≥ 4.5:1 для обычного текста и ≥ 3:1 для
крупного (≥ 24 px или ≥ 19 px bold).

### Пересобрать токены

Только если менялся seed или схема в `source/md3/theme.cpp`:

```bash
bash design/tools/build.sh
```

Скрипт считает схемы HCT-движком приложения и перезаписывает
`design/tokens.json` и `design/assets/tokens.css`. **Руками токены не
правь** — они должны совпадать с кодом, это проверяет `test_theme`.

### Иконка

```bash
node design/tools/build_icon.mjs
bash design/tools/render_icon.sh design/export/icon/icon.svg \
  design/export/icon/icon-256.png 256
```

Размеры для NACP/hbmenu: 1024, 256, 128, 64, 48; монохром — отдельно.

### PNG-утилита

```bash
node design/tools/png_tool.mjs info design/png/03-screens-home/home.png
node design/tools/png_tool.mjs sheet /tmp/sheet.png 4 icon-48.png icon-64.png
```

`info` — размер, тип цвета, минимальная альфа по краю; `sheet` — контактный
лист без сглаживания, чтобы смотреть мелкие размеры.

## 5. Визуальные правила

Полный список — `docs/design-tz.md` §2–§8 и `design/tools/BRIEF.md`. Коротко:

### Цвет

- Только роли: `var(--primary)`, `var(--on-surface-variant)` и т.д.
- Хексы допустимы только для: обложек-заглушек, слоёв поверх видео
  (белый/чёрный с альфой), служебной разметки доски.
- 37 ролей M3 в обеих темах; `surface` в тёмной — не чёрный.
- YouTube-красный — акцент, не заливка всего экрана.

### Типографика

- Только Google Sans (Regular 400 / Medium 500 / Bold 700).
- Минимальный кегль — 12 px.
- Названия видео — максимум 2 строки, затем многоточие.
- Без курсива, без ALL CAPS для русских слов (кроме микрозаголовков секций).

### Формы и сетка

- Базовая сетка 8 px; отступы 8 / 12 / 16 / 24 / 32.
- Поля экрана 24 px; карточки 16, крупные контейнеры 24–28, чипы — full.
- Тач-таргет ≥ 48×48, между соседними ≥ 8 px.
- Фокус геймпада: 3 px `primary` снаружи + подложка; виден на любом фоне.
- TV safe area: 64 px по бокам, 36 px сверху/снизу, без интерактивных
  элементов.

### Запрещено

`blur`, `backdrop-filter`, glass, mesh-градиенты, тени на карточках списка,
курсив, кегль < 12 px, иконки тоньше 1.5 px, Lottie, видео-фоны, 3D.

### Иконки

Только сабсет Material Symbols Rounded: `add arrow_back arrow_forward bolt
check chevron_right close cloud_off dark_mode delete error forward_10
fullscreen gpp_good hd high_quality history home info keyboard light_mode
lock more_vert movie music_note newspaper north_west open_in_new palette pause
play_arrow podcasts refresh remove replay replay_10 restart_alt schedule search
search_off settings shield skip_next speed sports_esports subtitles sync
thumb_up trending_up tune video_library visibility volume_off volume_up wifi
wifi_off`.

Разметка: `<span class="icon">имя</span>`, залитая — `class="icon fill"`.
Незнакомое имя отрисуется словом.

### Тексты

- Русский, без «Вы», без восклицательных знаков, без emoji.
- Тысячи через пробел: «1 200 000»; время `MM:SS` / `H:MM:SS`.
- Не писать «Материал 3».

## 6. Как добавить новый фрейм или экран

1. **Прочитай ТЗ.** Найди раздел своего экрана в `docs/design-tz.md` §4, а
   также §5 (компоненты), §7 (тексты) и §8 (доступность).
2. **Посмотри образец.** Открой `design/screens/_reference.html` и четыре CSS
   в `design/assets/`. Не изобретай разметку, если есть готовая.
3. **Выбери страницу.** Новый экран — в соответствующую `03-screens-*.html`
   или новую страницу, если это отдельный раздел (плеер, TV).
4. **Добавь фрейм.**
   - `id` в kebab-case, уникальный на странице;
   - внутри `.shot` с `.name` и `.spec`;
   - тёмная тема по умолчанию, светлая — для Home и Settings;
   - состояния: норма, загрузка, пусто, ошибка, фокус.
5. **Собери.** Отрендери **каждый** фрейм и посмотри PNG глазами: наложения,
   обрезанный текст, вылезание за 1280×720, иконки-слова, контраст.
6. **Прогони аудит.** `wd.mjs audit`; разберись с каждым пунктом, шум
   отметь в отчёте.
7. **Экспортируй.** PNG — в `design/png/<имя-страницы>/<frame-id>.png`.
   Иконки и SVG — в `design/export/`.
8. **Обнови документацию.** Если появился новый компонент или состояние —
   добавь строку в `docs/m3-matrix.md`. Если изменились токены — пересобери
   их и проверь `test_theme`.
9. **Открой PR.** Список файлов, список фреймов (id → что это), что
   проверено, найденные проблемы в общих CSS/ТЗ, места трактовки.

Не правь чужие фреймы «заодно». Один PR — одна тема.

## 7. Как передать дизайн в код

Дизайнер не пишет C++. Передача идёт через фрейм + спеку:

| Что нужно разработчику | Где взять |
|---|---|
| id фрейма | `data`/`id` во фрейме |
| размеры, отступы, радиусы | `.spec` под фреймом + redline |
| цвета | имена ролей, не хексы |
| состояния | отдельные фреймы `…-focus`, `…-loading` и т.д. |
| поведение | текст в `.spec`: что происходит по A/B, куда ведёт |
| тексты | финальные строки на русском |

Порядок для нового компонента:

1. дизайнер добавляет фрейм и состояние в `design/`;
2. разработчик добавляет виджет в `source/md3/widgets.cpp` и строку в
   `docs/m3-matrix.md`;
3. если нужен новый цвет/роль — сначала `source/md3/theme.cpp`, затем
   `bash design/tools/build.sh` (токены обновляются из кода);
4. проверка: `make test-host` (тема и M3), `tools/preview.sh` (PNG экранов);
5. расхождения «макет vs движок» фиксируются в PR, а не замалчиваются.

Движок не умеет blur/glass/сложные эффекты — это ограничение, а не лень.
Если макет требует запрещённого эффекта, предложи тональную поверхность,
скрим или другой вариант в рамках M3.

## 8. Чек-лист перед PR

- [ ] Все фреймы 1280×720 (TV — 1920×1080, внутренний холст 1280×720).
- [ ] Нет вылезания за фрейм, обрезки текста без многоточия, наложений.
- [ ] Все иконки из сабсета, не отрисованы словами.
- [ ] Кегль ≥ 12 px, тач-таргет ≥ 48×48, между таргетами ≥ 8 px.
- [ ] Контраст ≥ 4.5:1 (крупный ≥ 3:1) в обеих темах.
- [ ] Название видео — 2 строки; проверено строкой на 120 символов.
- [ ] Home держит 4/3/2 колонки без изменения высоты карточки.
- [ ] Состояния загрузки/пусто/ошибка есть для Home, Search, Player.
- [ ] Фокус геймпада виден на обложке и на тёмном фоне.
- [ ] TV: safe area 64/36, интерактив не заходит.
- [ ] Тексты по §7: без «Вы», emoji и восклицаний.
- [ ] `wd.mjs audit` разобран; шум отмечен.
- [ ] PNG отрендерены и лежат в `design/png/`.
- [ ] В PR нет правок `source/` и чужих страниц «заодно».

## 9. Частые ошибки

| Симптом | Причина |
|---|---|
| Иконка выглядит словом | имени нет в сабсете Material Symbols |
| Текст «пляшет» между фреймами | разная сетка/отступы; вернись к 8 px |
| Карточка выше/ниже соседней | фиксируй высоту, а не подгоняй контент |
| Фокус не виден на обложке | только цвет; добавь 3 px ring + подложку |
| Аудит ругается на тень | тень разрешена только у всплывающих поверхностей |
| Токены не совпали с кодом | `tokens.json` правили руками; пересобери `build.sh` |
| На TV всё мелкое | масштабируй канвас, не увеличивай кегли вручную |
| Длинный русский заголовок разъезжается | проверь 2 строки + ellipsis на 120 символах |

## 10. Куда писать

- Вопрос по ТЗ — issue с меткой `question`, списком, до начала макета.
- Нашёл ошибку в общих CSS — опиши в PR/отчёте, не чини молча.
- Нужен новый токен/компонент — сначала согласуй с разработчиком зоны UI.
- Спорный визуальный выбор — предложи два варианта рядом на одном фрейме и
  отметь рекомендацию.
