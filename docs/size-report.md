# Аудит размера и состава NRO (RB-09)

Дата: 2026-11-14. Сборка: `make -j`, devkitA64 GCC 15.2.0, `-O2`.
Артефакт: `TubeNX.nro` — **30 355 934 байт (28,95 МиБ)**.

## 1. Верхний уровень

| Часть | Размер | Комментарий |
|---|---:|---|
| `.text` (код) | 28 240 902 Б (26,9 МиБ) | статически слинкованы mpv/ffmpeg/curl/mbedTLS |
| `.data` | 1 571 120 Б (1,50 МиБ) | константы, таблицы, romfs-указатели |
| `.bss` | 21 773 832 Б (20,8 МиБ) | не входит в файл; heap/стеки/кэши во время работы |

| **итого `.nro`** | **30 355 934 Б** | ~30,4 МБ |

видео и TLS.

## 4. Что проверено

- `cacert.pem` используется только как fallback: при старте ставится
  `romfs:/cacert-trim.pem`, полный бандл подключается, если короткий не прошёл.
- Сабсет иконок — 63 глифа, 15 КБ вместо полного шрифта.
- Три начертания Google Sans — минимум для типографики M3 (Regular/Medium/Bold).
- Неиспользуемых изображений в romfs нет: `icon.png`/`icon.svg` — исходники,
  `icon.jpg` — обязательная иконка hbmenu.
- `stb_image_write` используется только в host-preview и не тянет лишнего в NRO.

## 5. Вывод

NRO не вырос относительно M3/M4 (30,27 → 30,34 МБ; +70 КБ дали новые строки и
отладочные символы). Дальнейшее заметное уменьшение возможно только за счёт
пересборки портлиб без ненужных кодеков/фильтров (вне зоны UI) либо выноса
шрифтов/CA на SD (ухудшает надёжность первого запуска). На alpha-этапе
размер приемлем.

Проверка:

```bash
export PATH=$DEVKITPRO/devkitA64/bin:$PATH
aarch64-none-elf-size build/*.o | sort -k1 -rn | head
ls -l TubeNX.nro
du -ab resources | sort -n | tail
```
