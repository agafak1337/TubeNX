# Архитектура TubeNX

Документ для нового разработчика: слои, потоки, сетевые бюджеты, жизненный
цикл и места, где смотреть логи. Рассчитан на 15 минут чтения.

## 1. Слои

```
┌──────────────────────────────────────────────────────────────┐
│ main.cpp          окно, framebuffer, главный цикл, applet-hook│
├──────────────────────────────────────────────────────────────┤
│ ui/               App (состояние) + screens (экраны), CFG     │
│ md3/              тема, UI-кит, виджеты, иконки               │
│ core/             canvas, шрифты, типы, потоки                │
├──────────────────────────────────────────────────────────────┤
│ yt/               InnerTube: лента, поиск, подсказки, потоки  │
│ player/           libmpv + software-рендер кадра              │
├──────────────────────────────────────────────────────────────┤
│ net/              libcurl, обложки, SNI-хук, таймауты         │
│ dpi/              SOCKS5-фрагментатор + HTTP-ретранслятор     │
├──────────────────────────────────────────────────────────────┤
│ libnx / devkitPro / portlibs (curl, mbedTLS, mpv, ffmpeg)     │
└──────────────────────────────────────────────────────────────┘
```

Правила зависимостей:

- `ui` знает про `md3`, `core`, `net`, `yt`, `player`, `dpi`; обратных
  зависимостей нет.
- `net` и `dpi` не знают про UI. `dpi` вообще написан на POSIX и собирается
  host-тестом.
- `player` не ходит в сеть сам: он получает URL локального ретранслятора.
- Всё, что можно проверить без консоли, вынесено в чистые функции и покрыто
  `make test-host`.

## 2. Главный цикл и кадровый ритм

Файл: `source/main.cpp`.

1. `appletMainLoop()` — обработка системных событий.
2. Hook `OnFocusState`/`OnResume` выставляет `g_focusDirty`; раз в кадр
   проверяется фон/сон и вызывается `player.onSleep()` / `player.onWake()`.
3. Раз в 30 кадров сверяется dock/handheld; при смене framebuffer
   пересоздаётся, состояние UI сохраняется.
4. `App::update(dt)` — ввод, анимации, фоновые ответы, таймеры.
5. `App::draw(canvas)` — только если `App::takeDirty()` вернул `true`.
6. `copyFrame()` — перенос в framebuffer: полная копия или только
   изменившиеся строки (RD-01).
7. `nwindowSetSwapInterval(1)` — кадр ждёт VBlank (PL-02).

`perf:` раз в 120 кадров:

```
perf: screen=1 upd=…/… draw=…/…(p95=…) flush=…/… ms
      fps=… drawn=… skip=… rows=…/720 slow=…
```

- `drawn`/`skip` — нарисованные и пропущенные кадры (статичный экран);
- `rows` — сколько строк реально скопировано;
- `p95` — 95-й процентиль времени отрисовки, цель < 8 мс;
- `slow` — кадры дольше бюджета.

## 3. Потоки

| Поток | Кто создаёт | Стек | Задача |
|---|---|---|---|
| Главный | `main()` | системный | ввод, update/draw, framebuffer |
| SOCKS accept | `dpi::startSocks()` | 512 КиБ | `accept()` на `127.0.0.1:1080` |
| SOCKS-клиент | на каждое соединение | 512 КиБ | handshake, фрагментация, relay |
| Relay accept | `dpi::startRelay()` | 512 КиБ | `accept()` на `127.0.0.1:8899` |
| Relay-клиент | на каждое соединение | 512 КиБ | `/u?u=`, Range, upstream через curl |
| Image workers | `ImageCache::start(2)` | 1 МиБ | скачивание/декод обложек, FIFO |
| InnerTube/фон | `threads::spawn()` | 1 МиБ | bootstrap, лента, поиск, `/player` |
| libmpv | libmpv | своя | демаксинг, декод, аудио |
| UI-таймеры | внутри App | — | сторож ленты/поиска/видео |

Правила:

- Не блокировать главный поток сетевым вызовом. Всё, что дольше кадра, — в
  фоновый поток.
- Все потоки с TLS/JSON получают явный стек: в newlib дефолтный стек мал и
  переполнение убивает процесс без исключения (`source/core/threads.hpp`).
- Общие данные защищены `std::mutex`; UI читает снимки, а не живые объекты.
- Поздний ответ отменяется по `generation`/`CancelToken`, чтобы не перерисовать
  устаревшую ленту.

## 4. Сетевые сессии и бюджеты

Файлы: `source/net/timeouts.hpp`, `source/net/http.cpp`.

### 4.1. SSL-сессии

В libnx одновременно живут **4 SSL-сессии**:

- **2** — UI (API + обложки), динамически;
- **2** — зарезервированы под плеер (видео + звук).

`SessionBudget::shared().reserveForPlayer(2)` не даёт UI занять последний слот.
Перед открытием видео простаивающие UI-соединения освобождаются. При
исчерпании — очередь с дедлайном, а не молчаливый отказ.

### 4.2. Таймауты

| Класс | Бюджет | Лимит ответа |
|---|---|---|
| bootstrap (`GET /`) | 10 с | 6 МиБ |
| API (`/youtubei/v1/*`) | 20 с | 8 МиБ |
| обложки (`i.ytimg.com`) | 8 с | 8 МиБ |
| probe (`generate_204`) | 9 с | — |
| плеер/служебные | 12 с | 4 МиБ |
| общий fallback | 30 с | 16 МиБ |
| файл в кэш | connect 20 с, low-speed 1 Б/с × 60 с | — |

Connect-таймаут = бюджет запроса, но не больше 25 с и не меньше 3 с. DNS-кэш
живёт 120 с. Значения можно переопределить в DIAG-сборке через `TNX_T_*`
(см. `net::setTimeout`).

### 4.3. Повторы

`decideRetry()` — чистая функция:

| Ошибка | Повтор |
|---|---|
| connect | да, для любого метода (тело не ушло) |
| timeout/io | идемпотентные — да; POST — только если ответ не начался |
| 5xx | один повтор для идемпотентных |
| 408/429 | да, с `Retry-After` (потолок 5 с) |
| 400/404 | нет |
| отмена вызывающим | нет |

Задержка: 400/800/1600 мс с потолком 3 с и jitter ±20 %.

## 5. Поток данных видео

```
InnerTube /player
   → pickStreams() выбирает adaptive 720p (itag 136 + AAC 140)
   → App::openPlayerStreams()
   → URL googlevideo подписан; mpv не умеет TLS в этой сборке
   → http://127.0.0.1:8899/u?u=<upstream>
   → relay: libcurl качает upstream (через SOCKS5/DPI или внешний прокси)
   → ffmpeg/libmpv читает локальный HTTP, декодирует H.264
   → player рисует RGBA-кадр в Canvas
```

Ретранслятор:

- принимает `GET`/`HEAD`, проверяет хост и схему;
- пробрасывает `Range`, отвечает `206` и `Accept-Ranges`;
- держит до 4 слотов: video 1, audio 1, other 2;
- при занятости отдаёт `503`, а не висит;
- для `googlevideo` подменяет SNI и перебирает имена-кандидаты;
- логирует `relay: <host> -> SNI …`, `-> 206, N байт`, `rate=… KB/s`.

## 6. Жизненный цикл

### Старт

1. `fs`/`romfs`/`socket`/`nifm`, лог версии и режима.
2. Framebuffer 1280×720 (handheld) или 1920×1080 (dock, fallback 720p).
3. `App::init()`: конфиг → тема → шрифты → `net::init()` → DPI/relay →
   image workers → bootstrap/проба в фоне.
4. Сплэш: прогресс, онбординг при первом запуске, переход в Home.

### Home / поиск

- `loadHome()` запускает фоновый запрос и увеличивает `generation`.
- Ответ применяется, только если `generation` совпал.
- Сторож: лента 30 с, поиск 20 с, видео 25 с — затем понятная ошибка и
  повтор.
- Обложки идут через `ImageCache` (LRU, лимит 48 МБ), UI не ждёт их.

### Видео

- `openPlayerStreams()` → `player.open()`; media state включается только на
  время воспроизведения.
- Раз в 5 с `player metrics:` (позиция, кэш, avsync, битрейты, дропы).
- Истёкшая ссылка → переоткрытие с текущей позиции.
- Выход: `player.close()`, media state выключается.

### Сон / фон

- `OnFocusState=Background` → `onSleep()`: пауза, `appletSetMediaPlaybackState(false)`.
- `OnResume` → `onWake()`: восстановление AO и позиции; при отказе — повторное
  открытие.
- Фоновые запросы, начатые до сна, не должны блокировать возврат.

### Выход

- `requestExit()` ставит `g_quit`; главный цикл завершает mpv, потоки, DPI,
  сервисы и возвращает управление hbmenu.
- «Медиа играет» в hbmenu не остаётся.

## 7. Конфиг и история

Файлы: `source/ui/config_io.hpp`, `source/ui/app.cpp`.

- `sdmc:/config/TubeNX/config.ini` — ключ=значение, версия схемы в заголовке.
- `sdmc:/config/TubeNX/history.tsv` — `#tubenx-history v2`, escaped TSV,
  дедуп по id, сортировка по `watchedAt`, потолок 100.
- Запись атомарная: `*.tmp` → `fflush`/`fsync` → старый в `*.bak` → `rename`.
- При чтении битого файла — откат на `.bak`, строка в лог.
- Если SD только для чтения — настройки живут в памяти, в UI висит баннер,
  ничего не теряется молча.
- Неизвестные ключи сохраняются при пересохранении (миграция без потерь).

## 8. Где смотреть логи

| Файл | Что внутри |
|---|---|
| `sdmc:/switch/TubeNX/logs/tubenx-<дата>.log` | полный лог запуска, ротация 2 МБ, 3 файла |
| `sdmc:/switch/TubeNX-boot.log` | копия текущего лога, её забирает `tools/pull-log.sh` |
| `sdmc:/config/TubeNX/diagnostics.txt` | сводка для отправки: режим, порты, настройки без секретов, последние ошибки, хвост лога |

Формат строки: `<uptime_ms> <LEVEL> <сообщение>`. DEBUG — только в
`-DTNX_DIAG=1`. Уровень можно поднять через `TNX_LOG=debug`.

Ключевые префиксы: `start`, `config:`, `dpi`, `relay:`, `socks:`, `ssl`,
`diag http:`, `feed:`, `video:`, `streams:`, `player:`, `player metrics:`,
`perf:`, `PL-03`, `display:`.
