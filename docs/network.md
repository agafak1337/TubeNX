# Runbook: сеть и диагностика

Как снять лог, что означают типовые ошибки и что делать. Все команды — с
компьютера; на самой консоли оболочки нет.

## 1. Снять лог с консоли

### Быстро

1. Соберите диагностическую сборку:

   ```bash
   export DEVKITPRO=/path/to/devkitpro
   make diag            # → TubeNX-diag.nro, DEBUG-лог
   ```

2. Скопируйте `.nro` в `sd:/switch/` (MTP или `make deploy`).
3. Запустите с hbmenu, воспроизведите проблему, выйдите в hbmenu.
4. Заберите лог:

   ```bash
   bash tools/pull-log.sh
   # → logs/hardware-boot.log (или logs/hardware-tubenx-<дата>.log)
   ```

Если MTP не виден, подключите SD напрямую и скопируйте:

```
sd:/switch/TubeNX/logs/tubenx-<дата>.log
sd:/switch/TubeNX-boot.log
```

### Через приложение

«Настройки → Диагностика → Скопировать лог» пишет
`sdmc:/config/TubeNX/diagnostics.txt`: режим, порты, настройки без секретов,
RTT, состояние bootstrap, последние ошибки и хвост boot-лога. Этот файл
удобнее всего прикладывать к отчёту.

### Что включить заранее

- `TNX_LOG=debug` — подробный лог без пересборки (переменная окружения
  задаётся в hbmenu/лаунчере, если среда это позволяет).
- `-DTNX_DIAG=1` / `make diag` — гарантированный DEBUG и диагностика HTTP.

## 2. Таблица ошибок

### 2.1. Сетевые коды libcurl

| В логе | Значение | Частая причина | Что делать |
|---|---|---|---|
| `curl 6` | не разрешилось имя | DNS, captive portal, нет Wi-Fi | проверить Wi-Fi в hbmenu; перезапустить |
| `curl 7` | не удалось подключиться | нет маршрута, заблокирован порт, DPI рвёт TCP | включить обход DPI, сменить режим фрагментации |
| `curl 28` | таймаут | медленный туннель, DPI-дроссель, перегруженный ретранслятор | см. §2.2 |
| `curl 35` | ошибка TLS handshake | SNI-подмена не подошла, строгий CA, DPI | см. §2.3 |
| `curl 52` | пустой ответ | сервер закрыл соединение, DPI | повторить; проверить прокси |
| `curl 55` | ошибка отправки | обрыв, «мёртвый» сокет | повторить; проверить сон/пробуждение |
| `curl 56` | ошибка приёма | обрыв на середине, DPI | повторить; уменьшить качество |
| `CURLE_ABORTED_BY_CALLBACK` | запрос отменён | ушли с экрана/новый поиск | норма, не ошибка |

В DIAG-логе строка запроса выглядит так:

```
diag http: GET https://www.youtube.com/youtubei/v1/browse HTTP/2
           reused=0 fresh=1 status=200 err=''
```

`reused=1` — соединение переиспользовано; `fresh=1` — новое. Если все запросы
`fresh=1` и медленные, соединения рвутся (DPI/таймаут).

### 2.2. `curl 28` и «3 КБ/с»

Симптомы: bootstrap отвечает, `browse` висит 20–30 с, в логе
`network_timeout`, лента не появляется.

Порядок:

1. **Отключить обход DPI** (Настройки → Обход DPI → выкл). Если стало лучше —
   проблема в фрагментации/SNI.
2. **Сменить режим**: `Split` → `Multi` → `TLS`. Режимы ведут себя по-разному
   у разных провайдеров.
3. **Проверить внешний прокси**: `socks5h://192.0.2.10:1080` (компьютер с
   VPN в той же сети). Прокси имеет приоритет над локальным обходом.
4. **Проверить Wi-Fi**: в логе `wifi: тип=… сигнал=…/3 статус=…`; сигнал 0–1
   и тип 0 — плохой канал.
5. **Проверить ретранслятор**: в логе `relay: rate=… KB/s`; если rate низкий
   на всех потоках — узкое место в канале, а не в коде.

### 2.3. `curl 35` / TLS

| Признак | Причина | Действие |
|---|---|---|
| `ssl: DoHandshake rc=0x1987b` много раз | `WOULD_BLOCK`, нормальный неблокирующий handshake | не ошибка; смотреть агрегат `ssl: handshake ok за N мс` |
| `SetSocketDescriptor rc=-1/ENOENT — норма` | libnx: сокет принят, новый fd не возвращён | не ошибка, handshake идёт дальше; не путать с отказом |
| `SetSocketDescriptor rc=-1`, errno ≠ ENOENT | сокет уже закрыт/невалиден | повторить; если постоянно — лог разработчику |
| `handshake пропущен` перед `curl 35` | устаревшая сборка: `-1/ENOENT` считался отказом | обновиться; в 1.0.0-diag.2+ этой ветки кода нет |
| `relay: SNI <имя> не подошёл` | подставное имя не принято | ретранслятор переберёт следующее; если все — нужен внешний прокси |
| `tls: режим проверки=1/2` | включён ChainOnly/None | вернуть полную проверку в настройках |
| `certificate verify failed` | CA-бандл/подмена имени | проверить `romfs:/cacert-trim.pem`; временно полный бандл |

Если TLS не проходит **только** для `googlevideo.com`, а API работает — это
блокировка CDN по SNI. Помогает подмена SNI (по умолчанию) или внешний прокси.

### 2.4. HTTP-коды

| Код | Где | Значение | Действие |
|---|---|---|---|
| `400` | `GET /` bootstrap | сервер не принял заголовки/HTTP-версию | смотреть DIAG-тело; это баг клиента, не сети |
| `403` | `/player` или видео | нужен PO-token/подпись, регион | сменить качество/клиент; внешний прокси |
| `404` | обложки `i.ytimg.com` | нет такого размера | норма: клиент перебирает размеры и ставит placeholder |
| `404` | API | устаревший endpoint/параметры | обновить клиент |
| `429` | API | rate limit | подождать; клиент повторит с `Retry-After` |
| `500/502/503` | API/relay | временная ошибка/нет слотов | повтор; для relay — уменьшить число потоков |
| `502` + `X-TubeNX-Error` | relay | upstream не отдал поток | смотреть `relay:` в логе, сменить SNI/прокси |

`404` обложек — **не** ошибка сети. В ленте на месте обложки будет тональный
placeholder с иконкой; на воспроизведение это не влияет.

### 2.5. SOCKS и ретранслятор

| Строка | Значение |
|---|---|
| `dpi socks: listen 1080` | SOCKS5 поднялся |
| `dpi socks: НЕ ЗАПУСТИЛСЯ` | порт занят/нет сокета — смотреть `socks: listen` |
| `socks: accept: … — пауза` | временная ошибка accept, цикл жив |
| `socks: handshakes за N с: ok=… fail=…` | агрегат, не чаще раза в 60 с |
| `relay: запущен (порт 8899)` | ретранслятор готов |
| `relay: 503` | все слоты заняты (video/audio/other = 1/1/2) |
| `relay: <host> -> SNI подменён на <имя>` | сработал обход для CDN |
| `relay: <host> -> 206, N байт` | видео отдаётся, Range работает |

Если `relay` не поднялся, видео не откроется даже при рабочем API. Проверьте,
что порт 8899 не занят и в логе нет `relay: ОШИБКА`.

## 3. Проверка на компьютере (host-тесты)

Эти проверки не требуют консоли и не ходят в интернет:

```bash
make test-host          # все host-тесты
```

- `tools/test_dpi.cpp` — SOCKS5 greeting/CONNECT/отказ, фрагментация
  ClientHello (27 280 конфигураций), ретранслятор, Range/206, ошибки, слоты,
  fuzz.
- `tools/test_net.cpp` — заголовки, редакция секретов, таймауты, матрица
  повторов, `SessionBudget`, лимиты ответа, цепочка обложек, отмена.
- `tools/test_innertube.cpp` — парсинг фикстур, выбор потоков, истёкшие ссылки.

Для живой проверки сети с компьютера:

```bash
# DNS и TCP до YouTube
getent hosts www.youtube.com
curl -v --max-time 10 https://www.youtube.com/generate_204

# через свой SOCKS5 (например, ssh -D 1080)
curl -v --socks5-hostname 127.0.0.1:1080 --max-time 10 \
     https://www.youtube.com/generate_204
```

На консоли эти команды выполнить нельзя — используйте лог.

## 4. Минимальный набор для отчёта

Приложите:

1. `diagnostics.txt` (Настройки → Диагностика).
2. `logs/hardware-boot.log` целиком, не обрезанный.
3. Модель/прошивку (экран «О приложении»).
4. Провайдера/регион и включён ли обход DPI.
5. Время возникновения проблемы и что делали до неё.

Без сырого лога проблема не диагностируется: пересказ «не работает» не
содержит кода ошибки.
